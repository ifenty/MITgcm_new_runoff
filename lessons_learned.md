# Active lessons

Keep each entry short and independently useful; load detailed evidence when its trigger applies.

```markdown
- [LL-001] <General lesson; confidence and scope>
  Trigger: <When this lesson matters>
```

- [LL-001] Write documentation dispositions and docstrings from the current source each correction round, not from templates; guard docstring/rule agreement with a test. Supported (RUNOFF-001).
  Trigger: a correction round changes a rule set, a public contract or scientific behavior.
- [LL-002] A tools-disabled runtime probe cannot establish role capability; run the live probe (allowed and denied Bash witness) after every ESX upgrade and before the first dispatch of an issue. Strongly supported (four kit defects, RUNOFF-001).
  Trigger: an ESX upgrade, a settings/permission change, or the first role dispatch of an issue.
- [LL-003] Every statement a project document makes about MITgcm runtime behavior (exf, exch2, cal) cites the source routine and lines it rests on. Supported (RUNOFF-001 rounds 1-4).
  Trigger: writing or reviewing schema/contract text that describes model behavior.
- [LL-004] Do not infer an MITgcm grid's kind (single lat-lon block vs exch2 cubed-sphere/LLC) from array geometry; blank tiles and LLC lat-lon-like facets defeat every heuristic. Have the user declare it, or read it from run metadata such as data.exch2, and test with blank-tile layouts. Strongly supported (RUNOFF-009 rounds 1-4).
  Trigger: any tool or reader that needs neighbour or layout information from grid output.
- [LL-005] Before claiming that a verification experiment exercises an edited MITgcm routine, check the build link target: experiments with their own `code/` copy compile that copy, not the edited file. Run oracle commands for one experiment one at a time, because every input variant shares its build directory. Supported (RUNOFF-012).
  Trigger: citing an experiment as coverage of edited model or package code, or running oracle tests in parallel.

- [LL-006] A documentation seal binds the whole inventory, and a reviewer's `candidate_signature` is sampled at the end of its turn, so editing an inventoried document after sealing both invalidates the seal and can strand a reviewer's signature — even for a one-line wording fix the reviewer itself called non-blocking. Reverting is not symmetric: it restores the seal but strands the signature the other way. Take optional documentation fixes inside the round that seals, or route them to the issue ledger, which is not inventoried. Strongly supported (RUNOFF-004: one cosmetic edit staled a twice-confirmed report, and reverting it dropped the approval count to 1 of 2 and cost a reviewer re-affirmation turn).
  Trigger: about to edit an inventoried document after its report is sealed or a reviewer has approved.
- [LL-007] A matching-digit oracle cannot detect a misplaced target: mass is conserved and the water simply arrives in the wrong cell. Measured on cs32, a cross-facet one-cell move of a 1st-percentile target whose two cells have bitwise-equal `rA` passes `compare_results.sh` at exactly the 10 required digits. Guard placement with a cell-exact check of the applied field, not with monitor digits. Strongly supported (RUNOFF-004 review A on `b8251cd1c`; 47 of 1189 targets have an equal-area wet neighbour).
  Trigger: claiming a digit-threshold oracle covers where runoff is placed, or choosing a tolerance meant to guard target identity.
- [LL-008] A discovery glob must carry an explicit scope predicate and report its out-of-scope matches, because discovery by name pattern silently equates "matches the pattern" with "is in scope for this model". Adding `lab_sea/input.rnof_sp_const` enrolled a sparse case in a timing check that models only the dense `pkg/exf` path; it survived five focused-suite passes and two independent approvals, because the scientific suite was in nobody's assignment. A predicate is enforced; remembering to grep is not. Supported (RUNOFF-004: the scientific suite failed at final verification on exactly this; `sparse_case()` is the predicate, and it reports SKIP with the reason and owning issue).
  Trigger: writing or reviewing a test that discovers its own cases by glob, or adding or renaming a verification input directory.
- [LL-009] Closing a hole implies enrolling a case that would catch its reopening, and a new guard must be demonstrated *failing* before it counts as a guard. Measuring correct behaviour once proves the code is right today; it does not stop a later edit from undoing it. Watch especially for a fix applied to sibling call sites where only one gets a case, and for a guard reachable only after an earlier check passes — reverting the first leaves every existing case green. Supported (RUNOFF-033: three instances in one issue — the accumulation-order premise behind `--rtol 0`, the `--min-dumps` guard, and the non-finite `target_cell_area`; against `target_coords_nan`, which was enrolled and which review B proved cannot pass via the skip path).
  Trigger: fixing a hole, adding a refusal or a guard, or recording a measurement as the reason a criterion is sound.
- [LL-010] When a stated acceptance criterion turns out to be unachievable in principle, replace it by measurement and record what the replacement does *not* cover — do not quietly satisfy it with a self-referential reference. A sparse-path case given its own reference tests reproducibility, not agreement with the path it is supposed to match, and that distinction has to be written where the contract is read, not only in the test. Measure the claim that the criterion is unachievable, too: the decisive form is to perturb the input by the smallest representable amount and show the criterion already fails. Supported (RUNOFF-005: a 1-ulp `runoff_flux` perturbation alone collapsed a case from 16 to 4 matching digits, reproducing the figure attributed to the dense/sparse difference; two of five cases turned out to meet the original criterion after all).
  Trigger: an acceptance criterion looks unmeetable, a reference is about to be generated from the code under test, or a replacement instrument is proposed for an issue's stated oracle.
- [LL-011] A test figure is worth nothing until the binary that produced it is known to postdate the source. Check build mtimes against the newest compiled source *before* running, not after, and state the ordering alongside the figure. "The change was comment-only, so behaviour is identical" establishes the behaviour, not the provenance of the number — rebuild instead of reasoning. The same discipline applies to a reviewer reusing its own earlier evidence: confirm the bytes it depended on are unchanged (`git diff --quiet <commit> -- <path>`) rather than inferring it from a reference-hash comparison, which cannot distinguish an added citation from a moved one. Supported (RUNOFF-005: a reported "54 of 54 on --mpi 2" came from a binary predating its own source edit, caught only because the implementer checked mtimes unprompted; and a reviewer's reuse argument flagged an unchanged Fortran file as changed because it had been newly cited).
  Trigger: reporting a test figure, citing earlier evidence as still current, or arguing that a change cannot have affected a result.
- [LL-012] An enrolment whose command cannot run on a clean tree is decorative, and a suite that has never executed the code it claims to cover will report success forever. Enrolment is real only when the enrolled command has been *measured failing* on a deliberate defect. The smell to look for is a suppression flag whose stated purpose is to tolerate a missing prerequisite — that converts an absent binary into a pass. Also check the two columns of a two-column oracle independently: one of them may be structurally blind. Supported (RUNOFF-013: `RNF_TENDENCY_APPLY_T`/`_S` executed under *no* configured command across all 57 scientific commands, because only one committed sparse file carries `runoff_temperature` and no command ran its directory, none carries `runoff_salinity`, and no enrolled input set `salt_EvPrRn`; a reviewer built mutant binaries and showed a wrong `X_ref` is caught at 1.7e-2 to 8.1e-2 while a sign flip leaves the Package column at exactly 0.00e+00 and is caught only by the two-run Total column, at 2.000e+00; `--allow-missing-rows` suppressed both the uncovered-row failure and the missing-binary exit and was deleted).
- [LL-013] A reachability claim is a measurement, not a reading, and the error runs in both directions. Source reading answers "what guards this", never "what input reaches it", and the gap is usually one input edit. Try the cheapest input first, and keep "needs another build" claims strictly separate from the ones that needed only a file. Supported (three consecutive issues recorded refusals as unreachable from source and were wrong: RUNOFF-005 `yearly_repcycle`, RUNOFF-033's non-finite `target_cell_area`, and three of five `RNF_NC_SERIES` refusals in RUNOFF-013, all three fired in seconds with a NetCDF file edit alone. The mirror error appeared in the same issue: a proposed hardening for two tracer names colliding is unreachable, because NetCDF refuses a trailing blank and collapses a trailing NUL to the same stored name, then refuses the duplicate).
- [LL-014] A listed entry that looks like coverage and measures nothing is invisible to inspection. Check such a list by perturbing an entry and watching the mechanism's output change — never by reading the list. Supported (RUNOFF-013 produced six instances of the one class: an instrument enrolled but never executed; three flavours of unmeasured `BUILD_SOURCES` path — absent from the list, a plain file that `os.walk` silently skips, and a path that does not exist and contributes exactly 0.0 with no error; a document outside the sweep's inventory; and a reviewer establishing a boundary by ten membership probes rather than by enumeration, which is the very error that reviewer had written into RUNOFF-036. Three successive hand-counts of one boundary gave 1, 10 and 44, and only the mechanical enumeration was right).
- [LL-015] A clean stale sweep has two blind spots, not one: a statement survives if no figures row is spelled the way the prose spells it, and a document outside the inventory is never swept at all — where no wording could help. When a row is meant as a guard rather than a regression test, spell a mechanical token: a dead `file:line`, a removed symbol, a deleted flag name. Supported (RUNOFF-013: two false statements survived a sweep reporting 0 hits over 6 figures; of three rows then added for one false paragraph, only the dead-`file:line` row caught a *reworded* version of the same claim, while both prose-clause rows fired solely on the bytes they were written from).
- [LL-016] A confident wrong boundary is worse than an acknowledged unknown one. When disclosing the limits of a mechanism, state the class and enumerate it mechanically; naming the instances someone happened to notice converts an unknown gap into false confidence. Supported (RUNOFF-013: the first disclosure of the uninventoried-document gap named two files when eleven plus a whole tree were outside the inventory, so the hand check it prescribed covered two of eleven, and `closed_issues.md:350` was still carrying in the present tense the same two stale tokens the disclosure existed to catch).
- [LL-017] Records may be edited during review; policy and executable witnesses may not. `project.py`'s signature scope and the documentation inventory are the *identical* path set, so the sealed report and every reviewer approval are invalidated by precisely the same files, in one event — and the framework already states the rule, in `project.administrative()`'s docstring: "Exclude records, not policy or executable witnesses, from acceptance." Keep a record-only correction round record-only; when a policy file must change, plan the re-affirmation into the round instead of discovering it. Supported (RUNOFF-013: an Arch edit to one policy file after the seal staled the report and stranded a reviewer approval in the same instant, causing correction round 3 outright; the two sets were then measured equal, with empty symmetric difference over 355 paths).
- [LL-018] Bookkeeping can cost more than the science, and the loop will not tell you so. A gate reports what it wants next, never what that instruction costs; a declared outage whose cause is structural still demands a probe every iteration and gates progress before anything else is reported. When the only pending work is a long verification nothing can accelerate, `loop_control.py pause` preserves the budget and keeps dispatched work alive — check it before idling through cycles. Supported (RUNOFF-013: loop iterations 13–85 produced no scientific work, consumed by 73 identical `claude mcp list` probes of a provider never configured plus 14 outage renewals, while a 107-minute suite ran; the pause was available throughout and was never suggested).
